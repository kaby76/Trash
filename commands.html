Trash — Command Reference

Invocation

Every Trash command is invoked through the dotnet trash dispatcher:

dotnet trash <name> [options] [args…]

Both the full sub-tool name (e.g. trparse) and the short alias without the tr prefix (e.g. parse) are accepted.

Ordering rules

  • Options before positional arguments. Named options (e.g. -t CSharp, -q file.xq, -o outdir/) must appear before any bare positional arguments (file names, XPath/XQuery expressions).
  • Use -- when an argument looks like a flag. If a positional argument starts with - (e.g. a query string beginning with -), place -- between the last option and the argument so the parser does not treat it as an unknown flag: 
    dotnet trash xpath -- '--//foo'
  • XPath / XQuery arguments containing /. Wrap the expression in single quotes to protect it from the shell. On MSYS2 / Git Bash on Windows, the shell rewrites leading / and // to Windows paths; run 
    export MSYS2_ARG_CONV_EXCL="*"
    once in your session (or add it to ~/.bashrc) to suppress this.
  • Stdin / stdout pipeline. Most commands read a parse result set (JSON) from stdin and write one to stdout, making them composable with |: 
    dotnet trash parse Grammar.g4 | dotnet trash xpath '//ruleSpec' | dotnet trash text
  • Reading from a file instead of stdin. Commands that normally read from stdin accept -f <file> to read a parse result set from a file instead.
  • Materialising results to disk. dotnet trash sponge writes parse result set data back to the original source files. Use it at the end of a pipeline after any transform: 
    dotnet trash parse *.g4 | dotnet trash rename -r "old,new" | dotnet trash sponge
